# Specification search accepted-result recovery

Goal: complete an existing search safely after a pause, ownership loss or temporary permission revocation, without losing a confirmed result or dispatching the provider again. Existing UI and request/response contracts remain unchanged.

Design: persist a versioned searched-item snapshot in the original reservation before dispatch. Use one transactional finalizer for the first result and known-result retries. Fresh current actor, project membership/category access, native material owner, gates/global mode and exact searched identity/old URL checks precede any BOM write. Merge the URL into the latest item only; unrelated changes survive. Atomically finalize the receipt, clear only its own item lock, retain the original audit, and append a deterministic reconciliation entry when recovering an already-audited attempt. Repeated/concurrent resolution is once-only. An uncertain provider outcome or old receipt without enough searched provenance never triggers a new dispatch or guessed write.

For another browser's new operation ID, retain the current two-step protocol: return outcome_unknown/reused_operation with the original ID first, so the existing client adopts it; settle only on a subsequent request naming that original ID. Do not return a completed result under a different ID because the existing client correctly rejects it. Other actors cannot inspect or redispatch a locked search.

Post-dispatch permission revocation must retain a known accepted result and its lock as unresolved, rather than terminal-failed with a released lock. Reproduce the suspected new-ID redispatch first. Target identity/URL conflicts retain existing conflict semantics and must not overwrite another result. Stale/old/malformed provenance stays unresolved; no automatic migration of receipts.

Alternatives considered: an additional background settlement worker or administrator UI would expand scope and add new workflows; a read-only receipt replay cannot recover the existing accepted result. Reuse the original retry as the smallest complete repair for the existing flow.
