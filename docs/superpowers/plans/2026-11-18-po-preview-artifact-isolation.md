# Isolate existing PO previews from issued artifacts

Goal: repair the existing Generate PDF workflow so previewing cannot replace an issued PO's bytes or download token. No new UI/feature, provider sends, live test documents or mutation activation. Work solo in the existing isolated worktree.

Evidence: seven exact paired vendor-po document/PO references have stale capabilities, while all existing files and current metadata are preserved. Current generatePOPDF's authorized preview calls the shared renderer without an immutable target; its legacy upload branch reuses purchase-orders/{project}/{sanitized-number}.pdf and replaces the token. The PO screen does not update stored references after preview. The same renderer supports actual legacy sending and native immutable send artifacts; preserve those paths.

Design: add a small preview publisher using a server-generated UUID path under purchase-orders/{project}/previews/, ifGenerationMatch=0, and one atomic save containing bytes and its download token. Only the authorized preview callable supplies the internal preview mode. Existing return shape, authorization, renderer layout and actual legacy/native sender paths stay intact. An independent immutable preview is preferable to a shared mutable preview slot (concurrent results can invalidate each other) or returning large callable byte payloads (changes the original transport/size limits). Preview artifacts add retained objects; retention remains an operational inventory item, not a new cleanup feature here.
