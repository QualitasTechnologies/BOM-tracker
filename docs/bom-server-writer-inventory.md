# BOM server-side writer inventory

This complements [`bom-client-writer-manifest.json`](bom-client-writer-manifest.json), which covers only direct browser Firebase SDK calls under `src/`. This page records server-side mutation and external-effect surfaces found by source inspection on `codex/bom-po-inward-integrated` at commit `99d8d09`. It is an inventory for review, not an authorization or cutover fence. A code path being present or tested does not prove its deployed configuration or real-user behavior.

## Cutover implications

- The per-project material marker currently covers selected materials, PO-send, spec-search, and MCP operations. It does not automatically fence user administration, communications, support/settings, project metadata, legacy PO drafts, or all Storage/provider paths.
- A retirement cutover needs a writer-by-writer map from each existing BOM control to its replacement UI and authoritative endpoint, with current project/role/category checks, conflict handling, audit, and recovery evidence.
- The notification retry fix and 56/56 emulator run prove only the isolated tested transaction and Rules scenarios. They do not establish deployed Firebase bindings, live Firebase user parity, Resend outcomes, provider shutdown/drain, or complete BOM-to-Pulse data/history reconciliation.
- Keep all native write flags and production markers off until the complete writer map, legacy-write fences, preflight, backups/restore, side-by-side acceptance, and rollback procedure are evidenced. The cutover drain policy still needs an explicit choice.
