User authorizes investigation and relevant fixes; original checkout, CRM, retirement permissions and provider-send restrictions remain. No new screens/features. Work solo in the existing BOM worktree; material release remains pending separately.

Verified: last 48 hours contain 221 backfill request timeouts at exactly 300 seconds and 288 incremental-sync `messages.get` 404 errors. Three pending backfill jobs were created in September, still have zero checkpointed messages, and have not been updated since September. The backfill schedule and both deployed Gmail workers have September revisions. Backfill schedule was reversibly paused on 16 November after saving its exact configuration; queued jobs/connection credentials untouched. Approval retries were intentionally paused by retirement work and stay paused.

Cloud Monitoring since 25 October attributes about 77% of Cloud Run allocation/billable instance time to backfill and about 22% to incremental Gmail sync. Daily backfill use was already high before 4 November; neither a new November job nor a November deployment explains it. These metrics are compute attribution, not a dollar-invoice reconciliation.

Local reproduction: deployed body cleanup uses `/\n(?:>.*(?:\r?\n)?)+$/`, whose ambiguous nested repetitions monopolize the event loop on a quoted line followed by fresh unquoted text. An isolated child times out after two seconds with only 24 nested quote markers. A network timer cannot interrupt this synchronous regex. Exact affected live email body has not been fetched; do not claim that message-level proof until observed runtime progress supports it.

Repair design: replace the ambiguous trailing-quote regex with a linear line scan, preserving new text and existing quote-boundary behavior. Treat a message-level Gmail 404 as an unavailable history entry, leaving it eligible for later backfill rather than writing a permanent exclusion or disconnecting the account. Keep other provider/auth failures visible. Bound full network/JSON operations and return the existing sanitizer fallback on an AI timeout. Add bounded, checkpointed backfill page processing and an invocation budget so one slow message cannot repeatedly consume a full five minutes. Protect checkpoint identity against an operator extending a job; retain query/cursor ownership and exact next-page continuation. Avoid raising timeouts or deleting/recreating jobs as a workaround.
